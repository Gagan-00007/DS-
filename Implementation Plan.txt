## What We're Building Here

Three things, in order:

1. **`backend/seed.py`** — a one-shot script that:
   - Wipes the existing (empty/stale) `attendance.db`
   - Creates 2 sections (`10-B`, `10-C`)
   - Creates 1 admin, 2 teachers, 4 students
   - Generates synthetic face embeddings (128-d random unit vectors) for each student — no webcam needed; they're stored directly into `enrolled_faces` via the same JSON path `recognition.py` reads
   - Creates timetable entries that are **active right now** (today's day-of-week, window around the current local time) so checkpoint scans find a live class immediately
   - Seeds 8+ historical absent records for one student to trigger the notification demo
   - Prints a summary table of all credentials

2. **`backend/dry_run.py`** — a self-contained Python script that:
   - Starts the FastAPI app in-process (using `TestClient` from `httpx`/`starlette`)
   - Walks through the full scenario: login → timetable check → entry checkpoint → liveness → attendance log → correction + audit trail → monthly notification trigger
   - Uses a synthetic frame burst (real face crop from a downloaded test image OR a programmatically generated face-like image) to drive the recognition step
   - Prints a pass/fail for each step

3. **Bug fixes found during code review** (two small issues to patch before running):
   - `checkpoint.py` line 88: `AttendanceRecord.date == now.date()` — `now` is a `datetime` but `date` column is `DateTime`; comparing `.date()` against a `DateTime` column works in Python but produces wrong SQL in SQLAlchemy. Fix: compare `AttendanceRecord.date >= today_start` and `< today_end`.
   - `main.py` `starlette` version conflict: installed `starlette==1.0.0` but `fastapi==0.115.0` requires `starlette>=0.37,<0.42` — this will cause an import error. Need to install compatible starlette.

## User Review Required

> [!IMPORTANT]
> **Synthetic face embeddings for the dry run**: The seed script generates random 128-d unit vectors as "face embeddings" for test students. This means the live checkpoint scan from a real webcam **will not match** these students (a real face embedding won't match a random vector). This is intentional for the seed/dry-run — the dry_run script injects the *same* stored embedding back as the "query" so recognition passes. For the actual demo, you'll run `enroll.py` with real photos to replace the synthetic embeddings.
>
> If you want real photos seeded right now (so a webcam at the door can recognize people immediately), tell me and I'll add a `--photos` mode to `seed.py` that calls `enroll.py` under the hood.

> [!WARNING]
> **Starlette version mismatch**: `starlette==1.0.0` is installed but `fastapi==0.115.0` needs `starlette>=0.37,<0.42`. The plan includes downgrading starlette to `0.41.3` as the first step. This is a pure version pin — no API surface changes needed in the app code.

### Fix 2 — `checkpoint.py`: day boundary for `today_end`

The `now.day + 1` above can overflow at end of month. Use `timedelta` instead:

```python
from datetime import timedelta
today_start = datetime(now.year, now.month, now.day)
today_end = today_start + timedelta(days=1)
```

> **Liveness for the dry run**: `detect_blink()` requires ≥3 frames with real facial landmarks for the EAR check. A synthetic frame burst (blank/solid images) will return `False` (no blink). Two options:
> - **Option A (default)**: Temporarily add a `BYPASS_LIVENESS=1` env var check in `liveness.py` — returns `True` when set, so the dry run can exercise the rest of the pipeline. The env var is never set in production, and we explicitly test the spoof case with `BYPASS_LIVENESS` unset.
> - **Option B**: Download a short real face video clip and use its frames as the burst.
>
> Plan uses Option A with a clear comment so it's easy to find and remove before demo day.
